Tests first, a person at every gate.

A plugin for Claude Code that takes a software idea from scattered sources to a verified build and a handover pack. It assumes no company, industry or stack.

It ships a command-line engine (gp), nine skills, six worker agents with limited tools, and a hook that pauses risky tool calls until the owner decides.

idea

The whole idea

Six rules. Everything else in the repository is there to enforce one of them.

  1. One tracker, one state. Asks, findings, failed runs and work are all items, each a file in one of five states. The agent works the ones it can do alone.
  2. Red before green. Every acceptance criterion gets a test suite before any code exists, and the suite is seen failing before the build. A criterion is done only on a passing full run of its accepted suite, on the current build.
  3. The writer never judges. The one who writes the suite never reads product code. The one who builds never edits a suite. The one who judges has not seen the builder's notes. A reviewer checks every suite version and every full run.
  4. People confirm the examples. Expected values come from examples a person confirmed. An open assumption keeps a criterion from being done, and a guess from memory never closes one.
  5. One-way doors are the owner's. A hook pauses a fixed list of risky tool calls. Accepting a suite, accepting a change to the pack and issuing numbers are the owner's. Nothing goes to production.
  6. Every handover says what stayed unproven. The pack includes a limits page: what no suite checked, which doubles stood in for real services, which assumptions are open. The certificate is left unsigned.

Not goals: production deploy or operations, inventing requirements (it asks), a no-human mode, any compliance claim, and mobile, desktop or embedded testing out of the box.

loop

One criterion, from nothing to done

  1. plate sources to one requirement file

    Briefs and notes become a canonical requirement. What it cannot settle is raised as an item for a person.

  2. shape design before code

    Architecture and interface contracts are written and the stack is decided, so there is something to test.

  3. design the suite, reviewed

    gus writes it, tracer case first. rex reviews it and the owner accepts that version.

  4. red before any build

    The suite runs before the build and must fail. A run that never reached the product does not count.

  5. build test-first

    ed builds one criterion at a time, on a recorded commit.

  6. verify run, judge, review

    eve runs it, tim judges, rex reviews the run. Failures go back to build.

  7. handover drafted, not sent

    dora writes the sponsor documents as local files. The owner signs and sends.

who decides

What the agent does, and what stays yours

The agent alone

  • Write and review suites, build, run, judge and score.
  • Draft the handover documents.

Only the owner

  • Accept a suite version, or a change to the pack.
  • Issue numbers, and sign and send the certificate.
  • Anything on the always-pause list.
  • The ladder: which parts of the pipeline wait for the owner, and which may run on their own.

The hook that enforces this matches text patterns and is not a sandbox. It has not yet been loaded by a live Claude Code session.

pitch

A second plugin in the same repository

The pitch plugin takes a foggy idea, often one discovery note or one sentence, to a won deal: a map of decision tickets, a Solution Statement, a proposal, a deck, and at the win a hand-off into this plugin's plate. Pricing, timeline, team and terms stay human inputs. It needs gp and the fence from this plugin.

status

What is proven, and what is not

Version 0.1.0, built on three fictional fixtures.

Shown so far

  • 451 tests passed on the day this page was written (2026-11-25), Windows 11, Python 3.13.
  • Each fixture goes from skeleton to red on every criterion, a reference build, green, reviewed, and done.
  • An independence check plants a blind spot that the builder's own tests miss, and the full run turns that criterion red.

Not shown yet

  • A real project. One small real tool, chosen by the owner, has to pass before this is called proven.
  • A live end-to-end run of the workers. The tests check structure, not how a model behaves on the files.
  • The hook in a live Claude Code session, the container runner, and mobile, desktop or embedded surfaces.

The full list of commands and mechanisms is in docs/reference.md.

try it

Run the engine

It runs on its own, with no Claude Code needed.

python bin/gp init my-project
python bin/gp doctor
python -m pytest -q

On Windows, use bin\gp.cmd. It needs Python 3.10 or newer, PyYAML and git. Tested only on Windows 11 with Python 3.13; Python 3.10 to 3.12, Linux and macOS are untested. The plugin install path has not been tried in a live session.
